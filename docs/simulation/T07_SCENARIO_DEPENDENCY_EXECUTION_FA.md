# T07 | اجرای وابستگی‌های ۲۴ سناریو و نمایش شواهد

**مبنا:** `v2` در کامیت `9a4ac3400262b6baf1e0534d646d6bfcfe14401e`.

## واقعاً چه چیزی پیاده شده است؟

- کاتالوگ **۲۴ برنامه دارای توضیح فارسی** و وابستگی صریح؛ API `GET /api/v1/admin/simulations/e2e/plans`.
- مرتب‌سازی توپولوژیک پیش‌نیازها؛ هنگام انتخاب یک سناریو، شناسه‌های وابسته نیز افزوده و ابتدا اجرا می‌شوند.
- برای **هر سناریو چهار بررسی واقعی فقط‌خواندنی**: ارتباط PostgreSQL (`SELECT 1`)، وجود جدول‌های اختصاصی، ثبت مسیر Spring MVC، و گیت اجرای TEST. این‌ها به معنی فراخوانی واقعی API یا تأیید Business Logic نیستند.
- هر گام در `simulation_e2e_step` نوشته می‌شود؛ پیشرفت از شمارش گام‌های پایان‌یافته حساب می‌شود. برای ۲۴ سناریو **۱۰۰ گام** برنامه‌ریزی می‌شود: ۹۶ بررسی + ۴ مرحله Fixture سناریوی ۱۴.
- اگر پیش‌نیاز شکست بخورد، مراحل بعدی بدون اجرای نوشتنی، `BLOCKED` می‌مانند و علت ثبت می‌شود.
- فقط `E2E-14` دارای عملیات نوشتنی محدود و ایزوله است؛ در صورت احراز نقش DB غیر SUPERUSER/BYPASSRLS و RLS چهار جدول، پرونده، ملک و دو مالک مصنوعی ایجاد، خوانده و جدا بودن TEST از REAL کنترل می‌شود. این هنوز **گردش‌کار کامل E2E-14** نیست (مدارک و HTTP واقعی ندارد).
- برای ۲۳ سناریوی دیگر، پیش‌نیازها واقعاً اجرا می‌شوند اما گام تجاری `BLOCKED` است، چون عملیات نوشتنی تمامی ماژول‌ها در سطح واقعی و TEST ایزوله نشده است. **هیچ PASS ساختگی** صادر نمی‌شود.
- دو نمای جزئیات: پنجره مستقل نتیجه E2E در زبانه «اجرای واقعی E2E»، و کشوی کاتالوگ. هر دو وظایف، وابستگی‌ها، جداول، مسیرها و گام‌های اجرایی را نشان می‌دهند.
- نمایش `PASSED/FAILED/BLOCKED` جدا از درصد پایان کار؛ **۱۰۰٪ ≠ قبولی E2E**.

## پیش‌نیازهای اجرا

۱. Flyway V58–V62 در PostgreSQL موجود باشند و بکاپ قابل بازیابی داشته باشید.
۲. نقش برنامه PostgreSQL نباید SUPERUSER یا BYPASSRLS باشد؛ در غیراین‌صورت E2E-14 عمداً مسدود می‌شود. هرگز محدودیت را برای فعال‌کردن آزمون حذف نکنید.
۳. برای آزمون انتخاب‌شده، جداول و مسیرهای لازم در نسخه در حال اجرا باید موجود باشند.
۴. ایجاد پرونده TEST **یک عملیات واقعی و پایدار DB** است؛ در محیط کنترل‌شده و با فضای آزمایشی مشخص اجرا کنید.
۵. اجرای این مرحله Migration جدیدی ندارد، بنابراین هیچ تغییری در سیاست‌های RLS قدیمی اعمال نمی‌کند.

## نحوه آزمون

- پس از نصب، `mvn -B -pl modules/quality -am test` و `npm run build` را اجرا کنید.
- در صفحه `/admin/simulations`، زبانه «اجرای واقعی E2E»، دکمه اجرای ۲۴ سناریو را بزنید.
- روی **مشاهده نتیجه** کلیک کنید؛ پنجره نتایج باز می‌شود. روی شناسه هر سناریو برای شواهد، خطا و مراحل همان سناریو کلیک کنید.
- از دکمه‌های ۲۴ برنامه سناریو، جزئیات هدف و وابستگی‌ها را مطالعه کنید.
- برای اعتبارسنجی آفلاین قرارداد، Node.js: `node tests/e2e/check_24_plans.mjs tests/e2e/scenario-plans.json`.
- نتیجه JSON را ذخیره کنید و مطمئن شوید هر سناریوی مسدود، دلیل دارد.

## آنچه هنوز باقی مانده است

اجرای **کامل تجاری** هر ۲۳ سناریوی دیگر (کاربر و نشست آزمایشی، دانش، OCR، خزنده، سازندگان، قراردادها، مصالح، امکان‌سنجی، مالی، AI، BFF و اعلان) و همچنین مسیر کامل E2E-14 به توسعه اختصاصی و ایزوله‌سازی سراسری نیاز دارد. مراحل صرفاً ساختاری را به‌اشتباه Business E2E نمی‌نامیم. برای فعال‌سازی امن، تست منفی متقاطع RLS، پوشش Queryها، اتصال کاربران TEST و sandbox خدمات خارجی ضروری است.

## محدودیت اعتبارسنجی این بسته

کامپایل Java با stubهای سازگار از امضاهای API (نه Spring واقعی)، بررسی AST نحو TSX، تست ۲۴ برنامه و وابستگی‌ها اجرا شدند. Maven و Vite واقعی و PostgreSQL آنلاین در محیط تحویل در دسترس نبود؛ پس Build نهایی و اجرای DB باید در سیستم شما تأیید شود.
