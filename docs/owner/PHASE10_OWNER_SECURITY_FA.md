# فاز ۱۰/۴۰ — مالکان و سهم مالکیت

مبنا: v2 @ 640af386f1ee795f9c070f821a54fb70a5c954f3

## هدف و مرزبندی
- حفظ صورت/مخرج صحیح سهم بدون تغییر قرارداد JSON و بدون اختراع واحد جدید.
- محاسبه دقیق با BigInteger (نه rounding دوازده‌رقمی) و منع مجموع بیش از واحد کامل.
- سریال‌سازی تمام نوشتن‌های مالکان از طریق قفل ردیف construction_case، مشترک با Property و Casefile.
- دفاع در خود سرویس: OWNER_READ / OWNER_WRITE، CaseAccessService، REAL فقط، TESTER ممنوع و جلوگیری از نوشتن روی ARCHIVED.
- نمایش نام/سهم به عضو فقط‌خواندنی، ولی null کردن کد ملی و موبایل بدون مجوز نوشتن معتبر پرونده.
- عدم ثبت کد ملی، شماره تلفن، متن آزاد یا سند هویتی در Audit؛ صرفاً caseId/propertyId.

## محدودیت‌های باقیمانده — حق ادعای PASS ندارند
- تغییرات حقوقی مالکیت/انتقال سهم، رضایت و امضا، تاریخچه حقوقی امضاشده: در مدل Owner فعلی وجود ندارند و نباید از CRUD استنباط شوند.
- RLS و FK دیتابیس مشترک در V3/V60 تعریف شده‌اند اما اجرای واقعی با نقش least-privilege و Testcontainers اثبات نشده است.
- HTTP واقعی 400/403/409 و E2E با دو مالک و غیرعضو، concurrency دو تراکنش مستقل هنوز لازم است.
- رابط کاربری درصدها را تقریبی نمایش می‌دهد؛ سرور مرجع قطعی سهم‌هاست.
- API فعلی برای ویرایش/حذف شرط If-Match ندارد؛ تغییرات متوالی stale-client با قفل صرف قابل شناسایی نیست.
