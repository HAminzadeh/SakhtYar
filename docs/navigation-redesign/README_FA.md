# Navigation R01 — بازطراحی منوی اصلی و مسیر پرونده ساخت‌یار

Baseline: `HAminzadeh/SakhtYar`, branch `v2`, HEAD `909d57770f33a76a793109ac13ef1e5973598383`.

## مسئله و تصمیم
- هدر پیشین دارای بیش از ده دکمه ناهم‌سطح بود و روی عرض‌های متوسط به scroll افقی و چینش غیرشفاف می‌رسید.
- پرونده دارای ۱۳ تب هم‌سطح (۱۲ بخش اصلی + دستیار اختیاری) بود و کاربر ترتیب پیشنهادی انجام کار را نمی‌دید.
- تغییر، فقط در لایه ناوبری و CSS است؛ endpoint، permission، وضعیت پرونده، داده واقعی و منطق کسب‌وکار را تغییر نمی‌دهد.

## ساختار منوی اصلی
- «پرونده‌ها»: دکمه اصلی، فقط با `CASE_READ`.
- «بازار و همکاران»: تحلیل بازار (`CASE_READ`) و مدیریت سازندگان (`USER_MANAGE`).
- «دانش و هوشمندی»: مرکز دانش، ورود دانش، مدیریت AI، رجیستری دستیاران و راهبری هوشمندی؛ هر گزینه با permission فعلی.
- «مدیریت سامانه»: کاربران، عملیات، رویدادها، تضمین کیفیت، شبیه‌سازی و تنظیمات پلتفرم؛ permission فعلی هر مسیر حفظ می‌شود.
- «راهنما»: دسترسی مستقیم.
- «حساب کاربری»: حساب، تنظیمات، آموزش و خروج در یک زیرمنو.
- روی عرض‌های کمتر از ۱۱۸۰ پیکسل گزینه‌های اصلی داخل Drawer لمسی و قابل پیمایش قرار می‌گیرند.

## ساختار مسیر پرونده
1. تشکیل پرونده: نمای کلی، مشخصات ملک، مالکان، مدارک، تصاویر.
2. مطالعات و برآورد: ضوابط شهرسازی، هزینه ساخت، امکان‌سنجی، تحلیل مالی، مقایسه سناریوها.
3. انتخاب سازنده: تطبیق سازندگان.
4. توافق و قرارداد: قراردادها.

دستیار هوشمند یک ابزار بین‌مرحله‌ای است و با همان permission سابق `AGENT_USE` نمایش داده می‌شود.
مراحل «نقشه ناوبری» هستند، نه گزارش تکمیل، تأیید حقوقی یا مرحله جاری واقعی پرونده. وضعیت واقعی همان badge `CaseStatus` API باقی می‌ماند.

## URL و سازگاری
- آدرس صفحات سطح اول تغییر نکرده است (`/cases`, `/admin/...`, `/market`, ...).
- زیربخش پرونده در Query URL نگهداری می‌شود: `/cases/<id>?section=urban-analysis`.
- لینک بدون `section`، مقدار نامعتبر یا `assistant` برای کاربر بدون دسترسی، به نمای کلی برمی‌گردد.
- دکمه «بخش بعدی پیشنهادی» تنها ناوبری است و هیچ تغییری در رکورد پرونده ایجاد نمی‌کند.
- پس از Refresh و Back/Forward مرورگر، زیرمنوی انتخاب‌شده از URL بازیابی می‌شود.

## نصب و کنترل
1. ZIP و فایل PS1 را در Downloads قرار بده؛ ZIP را دستی استخراج نکن.
2. به ترتیب `SelfTest`, `Audit`, `DryRun`, `ApplySource`, `Verify` اجرا کن.
3. `Verify`: بررسی ساختار route/section با Node و TypeScript، سپس `npm run build` در `frontend` و `git diff --check`.
4. پس از کنترل UI در عرض‌های ۳۷۵، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل، تغییرات را Commit کن.
5. `Rollback` با `-BackupDir` همان مسیری که نصب‌کننده گزارش می‌کند ممکن است.

## موارد پذیرش UI
- هیچ مسیر قابل دسترس قبلی حذف نشده باشد؛ دسترسی‌ها همان قبلی.
- هیچ دکمه به مسیر تعریف‌نشده اشاره نکند.
- هیچ مرحله‌ای صرفاً با جلو رفتن کاربر «تکمیل» یا «تأیید» تلقی نشود.
- زیرمنوها با صفحه‌کلید و کلیک باز شوند و Focus قابل‌مشاهده باشد.
- موبایل، RTL، حالت Dark و متن طولانی بررسی شوند.
- صفحات جدید API/Backend/Migration لازم ندارند؛ دیتابیس دست‌نخورده می‌ماند.

## وضعیت تست
Syntax TSX مستقل بررسی شده است؛ Build کامل روی محیط Windows هنوز اجرا نشده است. تست واقعی با مرورگر، صفحه‌خوان و مرورگر موبایل نیز READY_TO_VERIFY است. هیچ PASS برای این موارد ادعا نمی‌شود.
