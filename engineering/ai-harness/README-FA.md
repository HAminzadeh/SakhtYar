# SakhtYar AI Engineering Hub — نسخه 0.1.0

**ماهیت:** راهنمای نسخه‌دار برای همین دستیار ChatGPT و تیم توسعه، بدون Claude/Codex/MCP، بدون تغییر Backend، بدون API جدید، بدون ارسال داده.

**مبنای نام‌گذاری فهرست:** [76aaa77df6adc5b889e689007bf99b9a4f74af34](https://github.com/affaan-m/ECC/tree/76aaa77df6adc5b889e689007bf99b9a4f74af34) از ECC. سندهای حاضر بازنویسی‌های مستقل برای ساخت‌یار هستند، نه انتقال مکانیکی هوک یا runtime ECC.

## امکانات
- فهرست کامل ۷۱ نقش Agent و ۳۱۱ Skill بر اساس نام‌ها و دسته‌بندی‌های نسخه مبنا.
- راهنماهای متنی تولیدشده برای همه موارد؛ نقش‌ها/مهارت‌های منتخب با نگارش تخصصی `adapted`، باقی موارد `catalog` (چارچوب ابتدایی نه پیاده‌سازی کامل).
- ۵ گردش‌کار تخصصی: توسعه، مدیریت دانش، UI/UX، انتشار، عیب‌یابی.
- پنل ادمین `/admin/engineering` برای جست‌وجو و آموزش، بدون اجرای دستور.

## مرز عملکرد
- قرار گرفتن فایل‌ها در Git به معنی بارگذاری خودکار آن‌ها در ChatGPT نیست. برای استفاده در چت، متن `CHATGPT-PROJECT-INSTRUCTIONS.md` را به دستورالعمل Project اضافه و در صورت نیاز catalog / فایل‌های skill را Attach کن.
- Agentها نقش‌های متنی هستند و مستقلاً worker یا Process اجرا نمی‌کنند.
- گزینه‌های catalog فقط نقطه آغاز هستند؛ برای کار پرریسک به Skill اختصاصی کامل نیاز است.
- خروجی چت بدون ابزار شامل برنامه، محتوا، چک‌لیست، پیشنهاد و بازبینی اطلاعات فراهم‌شده است. اجرای تست، Git، و تغییر فایل local صرفاً با ابزار/اجرا در محیط مجاز ممکن می‌شود.
- پنل وب سندهایی را نشان می‌دهد که در Build فرانت‌اند گنجانده شده‌اند؛ اتوماسیون لحظه‌ای و اجرای Agent نیست. هیچ secret و تنظیم عملیاتی در این فهرست نیست.

## ساختار
- `catalog.json`: فهرست واحد اطلاعات عمومی
- `agents/*.md`: تعریف تک‌تک نقش‌ها
- `skills/*/SKILL.md`: روش‌های متنی و مراحل استفاده
- `CHATGPT-PROJECT-INSTRUCTIONS.md`: متن آماده انتقال به تنظیمات ChatGPT Project
- `frontend/src/pages/EngineeringHubPage.tsx`: نمای ادمین با حق دسترسی USER_MANAGE

## ایمنی و حاکمیت
این قسمت UI غیرمحرمانه و فقط‌خواندنی است. سطح `USER_MANAGE` در مسیریاب React اعمال شده است؛ این حفاظت صرفاً محافظ UI است و برای اطلاعات محرمانه نباید کافی تلقی شود.

## به‌روزرسانی
۱) در شاخه جداگانه فایل‌های راهنما را تغییر دهید. ۲) catalog و نسخه TS آن را از یک منبع تولید کنید؛ ۳) ساخت Frontend و بازبینی UI را انجام دهید؛ ۴) PR و تغییرات را تأیید کنید. هر ارتقای ECC upstream باید ابتدا با نیاز ساخت‌یار تطبیق داده شود.
